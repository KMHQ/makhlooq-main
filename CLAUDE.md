# CLAUDE.md

Website for the Khalai Makhlooq Star Citizen org (kmhq.org): fleet viewer, team roster, news and a Payload CMS admin.

## References

Read these for further context or when a task needs them; they aren't loaded automatically.

- `ARCHITECTURE.md`: How rendering, caching, data and auth fit together. Read it before changing any of them.
- `README.md`: Human-facing docs. Read it for setup and deployment steps.
- `payload-reference/`: Stock Next.js + Payload scaffold. Compare against it when changing framework config (Next, Payload, TypeScript, ESLint). Never edit it or import from it.

Keep `CLAUDE.md`, `ARCHITECTURE.md` and `README.md` up to date: when a change affects what one of them describes, update it in the same change.

## Commands

- Use pnpm.
- After changing Payload collections, globals or admin components, run `pnpm generate:types` and `pnpm generate:importmap`.
- `pnpm generate:db-types` regenerates `types/supabase.ts` from the live database. It needs `DATABASE_URL` and the globally installed `supabase` CLI. Until it's run, the file is hand-written from `supabase/migrations/`.

## Code conventions

- Prefer built-in Tailwind utilities over arbitrary values when the visual difference is negligible.

## Verification

- There is no test suite. After a series of changes, run `pnpm build`. It catches type errors and Cache Components errors (uncached data outside `<Suspense>`, prerender failures), which only show up at build time.

## Versioning

- Before every push, bump the `version` in `package.json` and commit it on its own as `chore: version`. Bump the minor version if the commits being pushed include a `feat`; otherwise bump the patch version.

## Gotchas

- Cache data with `"use cache"` + `cacheLife` + `cacheTag`, never `unstable_cache` or route segment config (`export const dynamic` is rejected under Cache Components). Keep `try/catch` outside `"use cache"` functions so failures aren't cached.
- Don't edit `app/(payload)/`; it's generated by Payload, and only `importMap.js` gets regenerated.
- The Payload adapter runs with `push: false`, so schema changes need a Payload migration (`pnpm payload migrate:create`).
- A new third-party domain for scripts, images, connect or frames has to be added to the CSP in `next.config.mjs`.
- The package must stay ESM (`"type": "module"`). The Payload CLI crashes without it.
- `public/draco/` is the Draco decoder `FleetScene` loads at runtime. knip reports it as unused; keep it.
- Hostinger Node.js Web Apps deploys from GitHub and runs `pnpm build` and `pnpm start`. There is no custom server.
- Hostinger's glibc can't load Next's native SWC binaries, so its builds fall back to WebAssembly SWC. That's why `pnpm build` uses `--webpack` (Turbopack needs native SWC) and the config is `next.config.mjs` (a `.ts` config fails to load under the fallback). Keep both, and the server `concatenateModules: false` webpack override that Payload's `next/og` import needs. `NEXT_TEST_WASM=1 pnpm build` reproduces Hostinger's build locally.
